**Version:** 2.0.0  
**Status:** Active Development

---

# Purpose

The Product Backlog is the master list of planned work for the project.

It provides a high-level overview of all features, improvements, bug fixes, research tasks, and documentation work required to complete the system.

Detailed implementation belongs in individual Task Specification documents (PDMP-006).

The backlog exists to answer:

- What should be built?
- What is the current priority?
- What is currently being worked on?
- What has already been completed?
- What is blocking progress?

---

# Workflow

Every backlog item follows the same lifecycle.

```text
Backlog
    │
    ▼
Ready
    │
    ▼
In Progress
    │
    ▼
Review
    │
    ▼
Testing
    │
    ▼
Done
```

If a dependency prevents progress:

```text
Blocked
```

# AI Context

Before beginning a new task, OpenCode should:

1. Review this backlog.
2. Select the highest-priority Ready task.
3. Verify dependencies.
4. Read the corresponding Task Specification.
5. Review the related architecture and development guide.
6. Begin implementation only after confirming the task is Ready.

OpenCode should not begin work on Blocked tasks.
